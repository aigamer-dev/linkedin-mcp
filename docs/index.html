Let your AI agent work with your LinkedIn.

linkedin-mcp is an open-source MCP server. It lets agents like Claude Code, Codex, OpenClaw, Gemini CLI, OpenCode and Cursor read your LinkedIn profile basics and publish posts, through LinkedIn's official API. Your app, your keys, your machine.

What it does

Two tools, kept deliberately small. Anything more would need LinkedIn permissions that individual developers can't get.

get_profile

Know who's signed in

Returns the authenticated member's name, email, photo and locale, so the agent knows whose account it is acting on.

create_post

Publish a post

Posts text to your feed, visible to the public or to your connections only. Up to 3,000 characters.

How it works

The server runs locally and talks to your agent over stdio. It is the only thing that ever holds your LinkedIn token.

Who it's for, and what for

Anyone who already works in an AI agent and wants LinkedIn to be one more thing it can do.

Turn a changelog, release notes or a PR into a launch post without leaving your terminal or editor.

Writers and creators

Draft with your agent, tweak the wording, publish in the same conversation. Keep a voice file in your project and let the agent follow it.

Agent and workflow builders

A small, readable reference for wiring an OAuth-backed API into MCP, with tests and a multi-agent installer.

Install

Needs Node.js 20+, npm and git. The installer finds the agents on your machine, builds the server and registers it. It backs up each config file before touching it.

curl -fsSL https://raw.githubusercontent.com/aigamer-dev/linkedin-mcp/main/install.sh | bash
./install.sh --list                  # see which agents were detected
./install.sh --agents claude,codex   # choose specific agents
./install.sh --dry-run               # preview changes
./install.sh --uninstall             # remove from all detected agents

Connect your LinkedIn account (one time)

  1. Create an app. At linkedin.com/developers/apps, using a LinkedIn Page you administer. App names can't contain "LinkedIn".
  2. Add two products: Share on LinkedIn, and Sign In with LinkedIn using OpenID Connect.
  3. Add the redirect URL http://localhost:3000/callback on the Auth tab.
  4. Add your keys to .env in the install folder, then authorize once:
    npm run auth
  5. Restart your agent. Tokens last about 60 days; re-run npm run auth to refresh.

What it can't do

LinkedIn's official API for individual developers is narrow. Better to know up front.

CapabilityStatus
Read your basic profileSupported
Publish text posts to your feedSupported
Edit headline, About, experience, skillsNot available in the official API

Messages, connections, search, analyticsNot available to individual developers
SchedulingNot built in

FAQ

Where do my credentials go?

Your client ID and secret live in a local .env file. The access token is saved at ~/.config/linkedin-mcp/token.json with owner-only permissions. Nothing is sent anywhere except LinkedIn's own API.

Could an agent post something I didn't approve?

An agent with this server connected can call create_post. Posts go out as you, publicly by default. Use your agent's tool-approval setting so every post asks first.

Is it safe for my LinkedIn account?

It uses the official OAuth API and the documented posting endpoint. It does not scrape or automate the website, which is what usually gets accounts restricted. Posting volume and content are still your responsibility under LinkedIn's terms.

Why do I need my own LinkedIn app?

So your credentials and rate limits are yours alone. Nobody else's app, server or secret is involved.

Does it work on Windows?

The installer script targets macOS and Linux. On Windows, build with npm and add node dist/index.js to your agent's MCP config by hand.
